# Separate Runtime Evidence from Identity Resolution

Runtime adapters report only Runtime Facts they can directly verify, using Runtime-specific fact shapes rather than one shared evidence dictionary. A dedicated Observed Evidence module interprets those shapes and owns required fields, Unknown Value rules, record-level validation, Evidence Identity, and share-safe Evidence Provenance; a separate Source of Truth resolution module then produces Identity Resolution. Missing source or Capability path normally produces Unresolved Identity rather than invalid evidence. Evidence is invalid only when its native record cannot be interpreted reliably; it remains visible with Unknown Values and Evidence Findings but cannot enter Identity Resolution or mutation planning. Evidence Identity is stable across mutable state, Revision, Capability Set, and display-name changes. Unified Inventory retains normalized Observed Evidence and Evidence Provenance, not complete native payloads, so evidence remains explainable without binding the schema to upstream formats or sensitive fields. Deduplication, version drift, and sync decisions use only Identity Resolution, never raw Runtime Facts, Observed Evidence names, or adapter-specific metadata.

Observed Evidence also derives Installation State from one Runtime record and may establish an Exposure State of `active`, `inactive`, or `unknown`. The cross-record state `ambiguous` belongs to Unified Inventory because it requires comparing multiple Exposures for the same Capability and Runtime.

Every Observed Evidence record declares an Evidence Subject. Only valid `installation` evidence may produce Installation, Capability, and Exposure entities. A `runtime-detection` such as unmanaged ZCode contributes Runtime presence and diagnostics without manufacturing an Installation Package.

One interpretable native record produces one Observed Evidence record. In particular, one `npx skills` lock record remains one evidence record with zero or more Runtime Exposure facts; it is not duplicated once per Runtime. If an adapter cannot stably identify or locate a malformed native record, it emits a Fact Collection Finding rather than inventing an unstable Evidence Identity.
