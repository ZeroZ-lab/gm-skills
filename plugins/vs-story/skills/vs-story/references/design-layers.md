# 滚动叙事形式清单(Design Layers)

动工前对照这份清单,明确这一页在每一层选了什么。目的不是全用,而是**有意识地选**,避免每次都退回到最熟的几样(状态渐变 + 路径流动 + 左右文字框)。

分类综合了 Oesch & West (2022) 的 scrollytelling 技法词汇表、Segel & Heer (2010) 的叙事可视化体裁,以及业界(Webflow / NYT / Apple)常见做法。本 skill 技术栈(Three.js + Anime.js)主攻带 ★ 的项,但任何一层的选择都应服务于主题,而不是被技术栈限制。

---

## A. 空间粒度三层(画什么)

### 画面层 — 整屏怎么编排

用户滚一下,整屏发生什么。宏观节奏。

| 形式 | 说明 | 适合 |
|---|---|---|
| ★ 固定舞台 + 文字步进(Sticky Stage) | 舞台钉在视口不动,文字滚动触发舞台换状态 | 空间叙事、系统机制、新闻调查 |
| 画面序列刷帧(Video / Image Scrub) | 滚动驱动一段视频或图片序列的帧,向上滚帧倒退 | 真实物理过程、装配、运动(Apple 拆解) |
| 分镜翻面(Section Reveal) | 每滚进入全新画面,上一屏整屏退出 | 阶段差异极大、不需连续舞台 |
| ★ 镜头漫游(Camera Dolly / Pan-Zoom) | 同一 3D 世界,滚动驱动摄像机飞行/穿梭/钻入容器 | 层级、尺度跨度大的题材 |

### 元素层 — 画面里的对象怎么动

| 形式 | 说明 | 适合 |
|---|---|---|
| ★ 状态渐变(State Tween) | 对象颜色/亮度/透明度/尺寸随滚动连续插值 | 几乎所有状态变化的基础 |
| ★ 路径流动(Path Flow) | 粒子/数据包沿预定路径运动,滚动控制位置 0→1 | 信号传输、数据流、因果链 |
| 路径绘制(Path Draw) | 一根线从无到有画出来,滚动控制描边长度 | 流程线、地图路线(SVG stroke-dashoffset) |
| 增删显隐(Enter / Exit) | 对象在某滚动点出现/消失 | 阶段切换、引入新角色。**必须可逆** |
| ★ 结构变换(Restructure) | 对象组成关系随滚动改变:拆分/合并/重组/嵌套 | 叙事力最强,机制感最重 |
| 布局迁移(Layout Shift) | 对象位置随滚动重排:排队/散开/聚拢/新阵型 | 同批对象在不同阶段的不同组织 |

### 细节层 — 质感微操

单看每个不显眼,合起来决定是"作品"还是"草稿"。

**节奏类**
- 变化后留观察停顿:核心变化别顶满整章,留 0.55–0.80 稳定区间
- 缓动而非线性:用 ease-in-out,不用 linear(linear 是模板 tell)
- 错峰(stagger):多对象变化时错开几十毫秒依次响应,不齐刷刷

**镜头类**
- 焦点权重分层:当前对象高亮,相关降权,背景压到 10–25%,每章只一个主焦点
- 微呼吸/漂移:摄像机或对象做极小幅度 sin/cos 浮动(reduced-motion 关)

**过渡类**
- 对称可逆:所有变化必须能由时间轴进度反推(向上滚能恢复状态的根本)
- 软跟随(lag):`pos += (target-pos)*0.1` 产生惯性拖尾,比硬切高级
- 降级一致:reduced-motion 换成状态切换不删功能,WebGL 挂了要有静态后备

## B. 叙事维度(怎么讲)

### 时间层 — 故事怎么推进

| 结构 | 说明 |
|---|---|
| 线性流程 | 1→2→3,因果递进。默认 |
| ★ 反馈闭环 | 执行→失败→回流→修正→重做。skill 要求"至少一次反馈" |
| 对比并置 | 两个方案/状态同时在场,滚动逐项对比。"为什么是 A 不是 B" |
| 缩放穿梭 | 宏观→微观逐层钻入,或反之 |
| 因果回溯 | 先抛结果,再倒推原因。悬疑式 |
| 循环 | 结尾回到开头,强调周期性(水循环、训练迭代) |

### 结构层 — 整体骨架

来自 Segel & Heer 的叙事可视化分类。

| 骨架 | 说明 | 适合 |
|---|---|---|
| 马天尼杯(Martini Glass) | 作者主导讲完核心,末尾把控制权交给用户自由探索 | 想让用户"先懂再玩"的交互式科普 |
| 交互幻灯片(Interactive Slideshow) | 整体骨架固定,每个分镜内允许局部探索 | 多步骤、每步可深挖 |
| 钻取式(Drill-Down) | 由浅入深逐层钻入细节 | 层级清晰的系统 |

> 关键决策点:故事讲完是"结束"还是"开放探索"?马天尼杯结构会多一个结尾的探索态。本 skill 默认结束,主题适合时可加探索态。

### 数据层 — 信息从哪来、怎么映射

| 类型 | 说明 |
|---|---|
| 概念图解 | 无真实数据,对象是抽象隐喻(TCP、神经网络属此) |
| 数据驱动 | 对象位置/大小/颜色由真实数值决定(人口、股价) |
| 计算可视化 | 画面是算法/模型的实时求解结果(流体、力学) |
| 比例编码 | 用面积/长度/角度编码数量(柱、饼、面积图) |

> 诚实约束:声称数据驱动,数值必须真实;是概念图解,就别假装有数据。

### 交互层 — 用户怎么参与

| 程度 | 说明 |
|---|---|
| ★ 纯滚动 | 滚轮是唯一输入(本 skill 默认,最克制) |
| 悬停揭示 | 鼠标停对象上显示详情/数值 |
| 点击切换 | 点候选路径/选项改变叙事走向 |
| 参数调节 | 拖滑块改参数看系统响应(学习率、阈值) |
| 拖拽操控 | 直接拖动对象改变其状态 |

> 交互越重,叙事控制越弱。解释性题材优先纯滚动,把交互留到结尾探索态(配合马天尼杯)。

## C. 呈现层(怎么看)

### 视觉层 — 美术语言

见 SKILL.md 的"美术方向"章节。拆细:调色板(≤3 色)/ 材质(发光/哑光/印刷/线框)/ 字体(衬线/无衬线/等宽)/ 空间感(正交扁平/透视纵深/雾化)/ 动效气质(机械精确/有机呼吸/印刷克制)。

### 媒体层 — 非图形媒体

来自 Oesch & West 技法。本 skill 不主攻,但作为形式盘点不缺席。

| 形式 | 说明 |
|---|---|
| 视频刷帧 | 视频帧绑滚动位置(Apple 产品页) |
| 音频滚动 | 音频播放/音量绑滚动(播客式叙事) |
| 自动播放媒体 | 揭示后自动播放的音视频 |
| 序列帧 | 预渲染的图片序列绑滚动 |

> 本 skill 若需这类媒体,用 Three.js 的 VideoTexture 或 HTML `<video>` + Anime.js 进度映射,不引入额外框架。

### 认知层 — 怎么引导理解

最抽象,最接近"叙事"本质。对应 SKILL.md 的"静帧测试""无文字测试"。

| 手法 | 说明 |
|---|---|
| 聚焦引导 | 镜头/高亮强制"现在看这里" |
| 逐步构建 | 从无到有往画面加东西,降低认知负荷 |
| 揭示对比 | 先给一版,再揭示另一版,制造"原来如此" |
| 保留悬念 | 先隐藏关键对象,到某章才出现 |
| 因果记忆 | 后面的变化要让用户想起前面(回流时认出"刚才走过的路") |

## 怎么用这份清单

设计一页时,自上而下各层挑一项(不是全用),写一句确认。例如:

> TCP 技术档案页 = 画面层[固定舞台] × 元素层[路径流动+状态渐变] × 细节层[可逆+缓动] × 时间层[线性+对比] × 视觉层[正交+双色印刷] × 认知层[聚焦+因果记忆]

换任意一层,气质和叙事重点就完全不同。**避免每次都用最熟的组合**。
