# gm-writing-topic-picker

选题决策器。判断一个选题值不值得写，以及从什么角度切入更有信息量。

## 何时使用

- 有一个模糊想法，不确定要不要展开写
- 在 2 到 3 个选题之间纠结
- 感觉选题太普通，想找到独特切入角度
- 写了一半发现没东西可说，需要重新聚焦

如果用户给的是大量零散素材、评论、笔记和草稿，并希望批量整理选题池，优先使用 `gm-topic-engine`。

## 输入

优先收集：

1. `选题/想法`：用户想写什么，可以是一句话、一个词或一个模糊感觉
2. `目标读者`：写给谁看
3. `写作目的`：想让读者理解、改变或行动什么
4. `用户经验`：有没有亲身经历、案例、观察或反面教训

信息不足时也继续工作，但要明确默认假设。

## 输出

| 维度 | 分析 |
|-----|-----|
| 价值判断 | 值得写吗，为什么 |
| 切入角度 | 2 到 3 个可能角度 |
| 核心观点 | 一句话总结文章要说什么 |
| 风险提示 | 可能写崩、写空或写俗的地方 |
| 推荐决策 | 写、暂缓、合并、缩窄或换角度 |

## 好选题标准

- 有的聊：作者有亲身经历、深度观察或真实案例
- 读者在乎：解决真问题，触及真痛点
- 有反差感：反常识、反直觉，或揭示隐藏机制
- 能落地：可以展开成结构，而不是只靠情绪撑篇幅
- 有边界：一句话能讲清楚，不是泛泛的大主题

## 工作流

1. 复述选题：用一句话压缩用户想写的内容。
2. 判断价值：从作者优势、读者需求、差异化和可展开性打分。
3. 找切口：给出 2 到 3 个可写角度，每个角度必须有不同的信息增量。
4. 定核心观点：选出最强角度，并写出一句可作为文章中心判断的话。
5. 标风险：指出最可能写空、写俗、写散的地方。
6. 给决策：建议写、暂缓、合并、缩窄或换角度。

## 输出原则

- 不为普通选题硬造高级感。
- 不把所有选题都判成“可以写”。
- 不只换标题，要改变信息结构。
- 优先保留用户真实经验和判断。
