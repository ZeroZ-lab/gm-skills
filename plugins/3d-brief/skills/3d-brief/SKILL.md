# 3D Brief — 创意、生产契约与制作总控

根据 3D 需求生成自包含的生产任务书：明确环境、Agent 分工、证据评分和条件式返工，获准后按任务书执行。一个入口，按意图推进。核心支持 Blender 产品资产与空间场景的静态成品；其他引擎、动画和实时交互可编写简报，但必须补充专属执行与验收方法，不宣称已具备同等完整的制作流程。

## 1. 确定本次终点

- “写提示词/做方案/做一个 3D 酒吧”等未明确执行的请求：交付 `<slug>_brief.md` 与简报检查结果。
- “直接做完/生成 .blend 和渲染/按这份 brief 开始制作”：同次任务内完成简报检查后进入制作。已获授权不重复询问。
- “继续/修复评审问题”：读取现有 brief、项目状态记录（新项目为 `_work/PROJECT.md`）和最近有效检查点，保留原有范围与预算。
- 只求创意方向：交付方向说明，到该终点停止。

保存到用户指定位置，否则当前目录；已有同名成果时保留原件，使用明确的修订文件。只有简报任务时不探查 GPU、不启动 Blender、不创建空制作工程。

## 2. 创意定向与事实研究

读取 [创意与研究](references/creative-direction.md)。已有参考优先；缺失的小决定采用可逆默认并记录。只有会改变目标、范围、预算或关键视觉方向的未知项才询问；“全推荐/你定”是采用已提出默认的授权，不再逐主题提问。

需要追问时从 [问题库](references/question-bank.md) 选当前阻塞决策，不把主题列表变成必填问卷。客观事实自行检索；真实还原、原创设定、推断分别记录。

完成条件：用途、范围、视觉方向、事实可信度和本次终点可确定；重大未决项明确列出，不能伪装成已确认事实。

## 3. 配置生产机制与生成契约

先读取 [生产配置规则](references/production-config.md)，根据任务风险配置环境检查、Agent 数量与职责、评分证据、轮数和退出条件；再读取 [八层模板](references/brief-template.md)，并按主体读取：
- 产品/拆解：[产品分支](references/product.md)
- 空间/环境：[空间分支](references/environment.md)
- 混合项目：两者都读，仅纳入授权范围内的内容。

模板是可定制的合同，不是不可更改的原文。所有占位符均须替换；不适用内容写明原因。简单 demo 可缩短篇幅，但仍保留范围、交付、预算/停止条件和实际验证方法。

按 [简报检查](references/contract-check.md) 检查并修复矛盾，仅简报任务输出 `<slug>_brief_check.md`；同次继续制作时将检查写入项目 `_work/PROJECT.md` 的“简报检查”章节，状态使用 READY 或 NEEDS_INPUT；READY 只表示简报可交接，不表示环境已可执行或作品已达标。交接给其他会话的 brief 必须自包含：嵌入所需分支要求与评审协议，不能要求接收者访问本插件路径。

完成条件：检查项全部有结论；未决事实不影响执行才可 READY。简报任务到此交付，附默认假设与剩余不确定项，不强制追加“现在开工吗”。

## 4. 授权制作与验收

只有第 1 步已授权制作时读取 [制作流程](references/production.md)，继续实际执行。制作项目采用八层模板 02 节的聚合布局，过程资料集中到 `_work/`，方向、资产、状态与规划合并为 PROJECT.md；将布局正文嵌入交接 brief。

明确区分 BRIEF_READY、PREFLIGHT、BUILDING、REVIEWING、VALIDATING、COMPLETE、PARTIAL 和 BLOCKED。评分、图片、命令退出状态均引用真实证据；工具不可用或图像不可检查时报告缺口，不能宣称验收通过。
