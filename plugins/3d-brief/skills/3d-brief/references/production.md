# Blender 制作流程

## PREFLIGHT

已授权制作才执行。先读 brief 与检查结果；NEEDS_INPUT 的重大未决项未解决时 BLOCKED。读取已有状态而不是重建。按 brief 的聚合布局写入文件，目录按需创建；旧项目沿用实际路径。

检查工作目录、Blender 可执行文件及真实版本、CLI、Cycles/设备可用性、现有资产和图像查看工具。记录实际能力与 brief 假设差异；允许原生替代，但改变交付或成本的方案需确认。没有 Blender 时保存简报与具体阻塞原因，不假称已建场景；安装软件或购买云资源不由模板默认授权。

设定可计时的总时长、完整评审最大轮数、付费资源上限。仅有“直接做完”而无资源预算时，提出明确的有界预算后确认；用户先前给过的预算直接沿用。无法观测 token 消耗时使用时间/轮数，不能虚报 token 计数。执行前预留最终全机位渲染与冷启动时间；启动新批次前估计是否可在剩余预算内完成。

## BUILDING

将环境、预算和授权写进 `_work/PROJECT.md` 的“任务状态”章节。按 brief 的五阶段顺序完成规划、灰盒、全机位低成本预览、资产替换和最终灯光。每阶段退出条件：全范围仍可渲染，新增项可见，检查点保存成功。

产品先验比例/装配/遮挡，空间先验容量/邻接/动线。维护资产逐项状态，不通过添加未授权资产弥补主要问题。

## REVIEWING

读取 [固定评审模板](review-template.md)，在项目中填好并冻结协议。每轮将全机位图、contact sheet、日志和合并评审 review.md 归档到 `_work/reviews/round_<n>/`，引用 `_work/checkpoints/` 中的场景检查点；按系统性问题优先顺序修复，同机位复拍。按 brief 配置的角色、人数、轮数与调度执行；不套用统一人数或轮数。

主 Agent 为唯一主场景写入者和集成负责人。评审只读，接收冻结契约与实际证据，不接收构建者自评分或说服性总结；主 Agent 将返回内容合并到 review.md。记录计划/实际人数、实际并发、每次调用与职责，槽位不足则分批，评审期间冻结场景。新上下文不等于无偏；未授权或不可用且独立性非硬门时按原职责自检，实际子 Agent 为 0 并声明独立性未验证；硬门时 BLOCKED。制作委派如启用，须隔离输出文件/集合并由主 Agent 验证后集成。

完整一轮包含冻结场景版本、全机位图、所有负责维度的评审及主 Agent 决策。一次补拍或单个评审不算完整轮次。首轮为 baseline；之后比较相同机位。相机变更建立新基线，保留总预算和已用轮数。

优先级：关键缺项 → 多图共同根因 → 单图局部问题。回退时修复或恢复有效版本；连续两次可比分数增量均小于 1 且未达标时，进行结构/布局/主构图/灯光重审，不靠加道具凑分。分数不可比或证据不全时先补证据，不推算增量。

最终退出需：已达到配置最小轮数、全部硬门和评分通过、回归要求满足，且最终冻结图集与冷启动验证通过。单轮方案首轮全过可进入验证，回归记 N/A；一旦修改已评审场景，须再做完整轮次。多轮方案最后两轮无实质性回退。预算或最大轮数先到则 PARTIAL；关键工具、事实或硬性独立评审依赖缺失则 BLOCKED。验收阶段技术证据补齐后由原职责复核；若修改场景则重新评审并重生成最终图集，不能只补日志宣称通过。

进入 VALIDATING 的条件是制作范围、视觉评分与回归要求已通过；尚待最终冻结图集和冷启动的技术项可保持 UNVERIFIED，补齐并复核后才判断 COMPLETE，避免要求验证前已有验证结果。


相机、曝光或灯光改动需记录；构图机位改变时更新版本并重新渲染上一检查点作比较，或明确旧图不可直接比较并重新建立基线。不可把不同机位的优劣称为同机位回归验证。

## VALIDATING

制作范围、视觉评分与回归通过后进入最终验证，保存最终场景并冻结版本；待验证的技术项继续标 UNVERIFIED。记录场景 SHA-256、Blender 版本、相机名、渲染设置、每个输出路径/尺寸、生成命令与退出状态到 renders/manifest.json。全部最终图须由冻结版本生成；之后任何场景修改使旧 final 集失效，需重新生成完整集。

关闭工作进程，通过 README 命令用新 Blender 进程打开交付场景，至少重渲 hero 到 `_work/validation/`；检查实际图像、尺寸、退出状态、缺失依赖。检查资源均已打包或使用相对路径；可行时复制交付目录到新位置复验，未做则明确注明。新进程重渲成功不自动证明换机器可移植。

COMPLETE 仅在质量门、全部交付与冷启动均有证据时使用。独立性有降级则单列，不能写“独立评审通过”。

## 停止与恢复

- 预算或最大轮数到限但未过门：PARTIAL，保留最优有效检查点，逐项列差距，不提高评分、不缩减合同。
- 工具/凭据/关键事实阻塞：BLOCKED，列具体依赖和可继续的下一步。
- 中断：`_work/PROJECT.md` 的“任务状态”章节记录 brief 版本、状态、授权范围、预算已用/剩余、检查点、最后成功命令、问题和下一步。恢复时沿用总预算，不重新计满额。
- 用户取消：停止启动新工作，安全保存当前结果并如实报告。

最终回复列实际路径、状态、已执行验证、证据支撑的评分、未验证内容与限制。不得把简报检查通过当作成品验收。
