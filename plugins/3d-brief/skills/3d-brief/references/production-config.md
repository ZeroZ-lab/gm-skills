# 生产配置生成规则

生成 brief 时读取本文件，将选定的配置具体化到 00、04、05 节。输出必须自包含；此文件是编写规则，不是执行者需要另找的依赖。配置是针对任务的初始策略，不是已经验证有效的最优参数。用户明确配置优先；继续项目沿用已确认人数、预算和验收，新增规则不自动覆盖旧契约。

## 环境与资源

00 节逐项列：能力/资源、用户要求、已验证事实及证据、待检查项、检查方法、不可用时的处理。覆盖 Blender/CLI/引擎、CPU/GPU、图片查看、资产依赖、子 Agent 与可用并发。仅简报任务不启动环境探查，事实列写“未检查”；参考机器不得写成当前机器。

分别记录制作授权、委派授权、总时间上限、付费上限、最终渲染和冷启动预留时间。无法观测 token 时使用时间与轮数。预算未明确时写执行前配置项，不把建议当授权。工具原生替代可自行采用；交付、关键参考、成本或独立性硬门改变需确认。缺少 Blender 阻塞制作；缺少图像检查能力阻塞视觉验收。

## 按职责配置 Agent

主 Agent 负责环境检查、主场景制作、问题分派、集成和最终验收。默认制作子 Agent 为 0；只有存在可独立验证的资产任务时才配置制作子 Agent，并限定输入、输出文件/集合、禁止修改范围和集成验证。多个写入者不得同时保存同一个 .blend。

评审角色先按风险拆分，再确定数量。以下是未指定配置时的起点，须说明选择理由：

| 任务风险 | 每轮评审子 Agent 建议数 | 合并职责 | 完整轮数最小/最大 |
|---|---:|---|---|
| 简单单体产品，无复杂内部结构 | 1 | 结构、视觉、覆盖与技术分节评审 | 1/3 |
| 拆解或多部件产品 | 2 | 结构/装配/技术；材质/灯光/构图/覆盖 | 2/4 |
| 常规多区域空间 | 3 | 规划/运营；资产/材质；灯光/构图/技术 | 2/4 |
| 大型高密度空间 | 4–6 | 按独立专业风险拆分，确保全部评分维度有人负责 | 3/5 |
| 严格 Skyline 配置 | 6 | 规划、运营、室内、餐桌细节、夜景灯光、技术 | 4/5 |

建议数仅在委派已授权且工具可用时执行。brief 必须写出本项目的确定人数，不保留范围：主 Agent 数、制作子 Agent 数、每轮评审子 Agent 数、并发上限，以及逐轮使用新上下文时的累计调用上限。并发包含主 Agent；槽位不足时分批，只读评审可并行，主场景在评审期间冻结。若时间不足以按原职责分批完成，报告预算缺口。

每个角色列：ID、负责维度、不负责内容、输入证据、输出格式、读写权限、依赖、调度顺序。评审输入是任务目标、冻结契约和实际证据，不携带构建者的自评分或说服性总结；回归所需的上一轮图和未解决问题可以提供。视觉职责读原图，结构/运营职责还需尺寸、资产/区域表，技术职责需 .blend、脚本、依赖和运行日志。所有评审只读，主 Agent 汇总到单份 review.md 并指派修改。

声明独立评审是否为硬门。非硬门且委派不可用/未授权时，主 Agent 按相同职责分节自检，实际子 Agent 数为 0，独立性未验证；硬门时保持未通过，列出恢复条件。角色数量不等于真实派出数量，多角色自检不冒称多个 Agent。同模型新上下文也不证明评审无偏。

## 评分与证据

05 节分成“硬门表”和“评分表”。硬门逐项定义条件、验证方式和证据，状态 PASS/FAIL/UNVERIFIED；资产缺失、关键视觉故障、交付不可打开等不能靠高分抵消。

评分表每行包含：维度、权重、门槛、满分表现、常见扣分及对应档位、证据类型/机位、负责角色。权重合计 100；默认总分至少 90、单项至少满分的 85%。90%/70%/0 档分别对应轻微瑕疵、明显缺陷、缺失或失效，针对项目填写具体例子；分数是证据支持的判断，不是客观测量。未知证据标 UNVERIFIED，不能计 0 或猜分后计算总分。硬门失败可继续诊断评分，但不得验收。

## 迭代与退出

完整一轮包含冻结场景版本、全机位图、所有负责维度的评审及主 Agent 决策。一次补拍或单个评审不算完整轮次。首轮为 baseline；之后比较相同机位。相机变更建立新基线，保留总预算和已用轮数。

优先级：关键缺项 → 多图共同根因 → 单图局部问题。回退时修复或恢复有效版本；连续两次可比分数增量均小于 1 且未达标时，进行结构/布局/主构图/灯光重审，不靠加道具凑分。分数不可比或证据不全时先补证据，不推算增量。

退出需：已达到配置最小轮数、全部硬门和评分通过、回归要求满足，且最终冻结图集与冷启动验证通过。单轮方案首轮全过可进入验证，回归记 N/A；一旦修改已评审场景，须再做完整轮次。多轮方案最后两轮无实质性回退。预算或最大轮数先到则 PARTIAL；关键工具、事实或硬性独立评审依赖缺失则 BLOCKED。验收阶段技术证据补齐后由原职责复核；若修改场景则重新评审并重生成最终图集，不能只补日志宣称通过。

进入 VALIDATING 的条件是制作范围、视觉评分与回归要求已通过；最终图集和冷启动技术项可以待验证，补齐并由原职责复核后才判断 COMPLETE。单轮方案的“通过”不要求提前获得尚未生成的冷启动证据。
