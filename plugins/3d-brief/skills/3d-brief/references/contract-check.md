# 简报交接检查

生成后执行一次语义审查，不用“标题齐全”代替内容检查。修复可自行解决的矛盾；重大未决项才询问。

| 检查 | 通过条件 |
|---|---|
| 八层合同 | Goal、Environment、Protocol、Build Order、Domain Spec、Review Loop、Rubric、Validation 均有执行内容 |
| 事实与创意 | 型号一致；来源可追溯；设计值/推断有标签；无影响身份或结构的未决事实 |
| 范围与数量 | 资产唯一 ID；每行有计数单位和数量；族/实例不混算；容量、尺寸、区域和交付一致 |
| 证据覆盖 | 每项必需资产/区域映射有效相机 ID；机位有景别、方位和职责；能验证中近距结构 |
| 评分 | 权重合计 100；每维度门槛为其满分的 85%；有项目专属锚点；硬性缺项不能被其他高分抵消 |
| 预算 | 最少轮数不超过最大轮数；时间/付费上限明确或标为执行前配置；最低交付与预算不符时提出缩范围方案，不悄悄降低标准 |
| 评审 | 固定提示词、输入和输出协议已嵌入；图像证据与技术证据分开；无独立评审时诚实降级 |
| 交接 | 无未替换模板占位符；无本插件绝对路径依赖；冷启动方式和交付清单明确 |
| 文件布局 | brief 内嵌聚合布局；过程资料归入 `_work/`，工作记录合并，目录按需创建；旧项目或用户指定布局有实际路径映射 |
| 授权 | 本次终点明确；制作授权与资源授权分开；已有授权被保留 |

仅简报任务将结果保存为 `<slug>_brief_check.md`；同次继续制作时写入 `_work/PROJECT.md` 的“简报检查”章节：状态 READY/NEEDS_INPUT、逐项结论、修复内容、仍未决项、采用的假设、执行前环境与预算配置项。

READY 表示可交接的合同。环境尚未探查/预算待配置时可 READY，但制作仍须通过 PREFLIGHT。影响主体身份、必需范围或验收含义的未决项必须 NEEDS_INPUT。不要输出虚构的作品评分。
