## 03 / BUILD ORDER — 构建顺序 ⚙

1. **美术圣经与规划集**：把简报转成美术圣经、<结构规划>、资产清单、材质语言、固定相机集、技术预算、验收地图。
2. **可渲染灰盒**：覆盖全部范围的灰盒——<主体结构>、比例、全部固定相机就位。用真实尺寸与尺度代理。
3. **立即预览评审集**：立刻渲染低成本预览，暴露布局、比例、构图、相机失败。
4. **资产族替换**：以连贯的资产族替换占位体——先宏观构图，再功能结构，最后近距制造细节。每轮替换后保持全场景可渲染。
5. **最终陈设与灯光**：材质分离、环境语境、灯光层级、叙事道具、相机构图。高采样与昂贵效果只留给确认的最终视角。

## 04 / REVIEW LOOP — 证据驱动评审 ⚙

固定评审集 = 07 节第 8 小节的最终相机清单。至少 <N≥3> 轮完整循环：

**构建/修改 → 渲染固定评审集 → 检视真实像素与 contact sheet → 诊断 → 修复 → 同机位重渲**

批评只认渲染出来的图像——不认代码、场景树、视口描述或构建者总结。每条发现记录：相机/文件证据、严重度、受影响子系统、可能根因、可执行修正。影响多帧的系统性问题先于孤立抛光。

评审员（新鲜上下文子代理，输入与输出受以下条款约束，防止"被审者充当自己的公诉人"）：

1. <评审员 1——领域与判断范围>
2. <评审员 2>
3. …共 4-6 位，按本项目关键风险面配置

**评审员输入（由构建者原样转发，不得增删、编辑或降质）**：完整 07 节（含资产清单、相机职责表、致命失败清单）+ 评分表 + 该轮全分辨率原始渲染文件（禁止重编码、降分辨率或压缩喂图）+ contact sheet。评审提示词按固定模板生成（只填轮次号），禁止加入"已修复/已完成验收"等倾向性叙述。

**评分与归档**：评审员输出固定格式——逐维度数值分 + 扣分证据（相机/部件引用），扣分必须能落到评分锚点。当轮维度分 = 各评审员该维度的最低分（防挑高分汇总）。每轮归档 `renders/round_<n>/`（全机位，禁止覆盖）与 `reviews/round_<n>/<评审员>.md`；回归对比必须引用归档路径；评审分数一经产出即归档，禁止弃评重评或换评审员重掷。

**证据下限**：固定评审集是下限不是上限——评审员可要求对任意清单行项补拍特写；每个资产清单行项必须至少在一个中景/特写机位可辨认，否则按未完成计。

**技术维度的证据通道**：技术评审员豁免"只认像素"原则，可直接读 .blend 与 scripts/，输出审计报告（命名、集合、实例化、路径、修改器保留）。

**降级声明**：执行环境无子代理能力时，明确降级为主代理自检，并在最终交付中声明"评审独立性未验证"。

**回归纪律**：每轮修复后将同一相机与上一版对比，标注 improved / unchanged / regressed。材质回退必须修复或回滚。每轮完整循环后更新 contact sheet、TASK_STATE.md 与评分证据。

**停滞升级**：连续两轮完整循环总分提升不足 1 分时，强制做结构改造——重新审视 <列举该项目的结构性层面，如布局/层级/主构图/灯光架构>，而不是继续堆小道具、表面噪波或装饰光。
