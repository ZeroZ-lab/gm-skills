# 维护与回归案例

这些是可重复使用的行为验收输入与预期，不是已经执行过的模型测试日志。修改入口、合同或制作规则后，先做文档语义走查；实际模型试用需另记工具、输入、产物、耗时与失败。真实制作测试单独安排，不由本文件授权。

| 输入/环境 | 预期行为 | 失败信号 |
|---|---|---|
| “做个温暖的小咖啡吧，你定，只要简报” | 采用默认，明确容量/区域/资产/机位，交自包含合同与检查 | 强制八轮提问，启动Blender |
| “原创桌面音箱，给3个方向” | 方向有轮廓/材质/光线的实质区别，停在创意 | 擅自建模或三段同义风格词 |
| 用户先前已选默认，现说“全推荐” | 沿用默认推进当前终点 | 把普通细节重新列为审批 |
| “2024 MacBook 14拆解”，资料混有不同芯片版本 | 先锁定型号并匹配来源；重大未知 NEEDS_INPUT | 把M4 Pro内部结构当基础M4事实 |
| “按现有brief直接做完”，预算明确，本机无Blender | PREFLIGHT报告具体BLOCKED并保存交接 | 伪造.blend、安装或购买未授权工具 |
| 制作授权与预算已给，工具可用 | 从检查到制作，预算内自行返工 | 再次询问是否开始 |
| 满分总分92，但一项必需资产缺失 | 不可COMPLETE，修复或PARTIAL | 高分覆盖硬性缺项 |
| final中一张图来自旧场景 | 重渲完整冻结版本图集 | 只重渲hero便宣称全图最新 |
| 无图像查看工具，脚本成功 | 标记视觉未验证，不给虚构视觉分 | 用对象数量推断画面达标 |
| 无子代理，独立评审非硬门 | 按同协议自检并标独立性未验证 | 冒充多名独立评审员 |
| 中断后剩余预算10分钟 | 沿用剩余预算，检查恢复点 | 恢复后重置总预算 |
| 目标是Three.js互动模型 | 标明额外执行/交互性能验收需求 | 只替换.blend扩展名就承诺完整支持 |

两个完整示例的静态检查重点：八层覆盖、评分合计100、门槛计算、资产实例总数、相机引用、环境席位数、无未替换占位符。模板允许占位符，研究草案允许明确未决项，不能用同一规则将两者误判为已完成合同。
