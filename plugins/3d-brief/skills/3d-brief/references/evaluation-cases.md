# 维护与回归案例

这些是可重复使用的行为验收输入与预期，不是已经执行过的模型测试日志。修改入口、合同或制作规则后，先做文档语义走查；实际模型试用需另记工具、输入、产物、耗时与失败。真实制作测试单独安排，不由本文件授权。

| 输入/环境 | 预期行为 | 失败信号 |
|---|---|---|
| “做个温暖的小咖啡吧，你定，只要简报” | 采用默认，明确容量/区域/资产/机位，交自包含合同与检查 | 强制八轮提问，启动Blender |
| “原创桌面音箱，给3个方向” | 方向有轮廓/材质/光线的实质区别，停在创意 | 擅自建模或三段同义风格词 |
| 用户先前已选默认，现说“全推荐” | 沿用默认推进当前终点 | 把普通细节重新列为审批 |
| “2024 MacBook 14拆解”，资料混有不同芯片版本 | 先锁定型号并匹配来源；重大未知 NEEDS_INPUT | 把M4 Pro内部结构当基础M4事实 |
| “按现有brief直接做完”，预算明确，本机无Blender | PREFLIGHT报告具体BLOCKED并保存交接 | 伪造.blend、安装或购买未授权工具 |
| 制作授权与预算已给，工具可用 | 从检查到制作，预算内自行返工 | 再次询问是否开始 |
| 满分总分92，但一项必需资产缺失 | 不可COMPLETE，修复或PARTIAL | 高分覆盖硬性缺项 |
| final中一张图来自旧场景 | 重渲完整冻结版本图集 | 只重渲hero便宣称全图最新 |
| 无图像查看工具，脚本成功 | 标记视觉未验证，不给虚构视觉分 | 用对象数量推断画面达标 |
| 无子代理，独立评审非硬门 | 按同协议自检并标独立性未验证 | 冒充多名独立评审员 |
| 中断后剩余预算10分钟 | 沿用剩余预算，检查恢复点 | 恢复后重置总预算 |
| 只要简报，不制作 | 仅生成 brief 与 brief_check 两个文件 | 创建空制作工程或 _work/ |
| 新项目已授权制作 | 顶层只放 brief、最终场景、README、renders/、按需 assets/ 与 _work/；工作记录集中 PROJECT.md | 顶层散落方向、资产、规划、状态或脚本文件 |
| 完成一轮多机位评审 | 图片、contact sheet、日志和单份 review.md 聚合在 _work/reviews/round_<n>/，引用场景检查点 | 图片与评审分散两套轮次目录，或合并时丢失证据 |
| 尚无纹理或验证产物 | 按首次实际写入创建对应目录 | 预建整套空目录 |
| 继续采用旧布局的项目 | 沿用原路径并记录映射 | 自动搬移场景、破坏资源引用或重建副本 |
| 用户指定不同输出布局 | brief 写明实际路径映射，生成和验证使用同一路径 | 强制新布局或清理用户文件 |
| 目标是Three.js互动模型 | 标明额外执行/交互性能验收需求 | 只替换.blend扩展名就承诺完整支持 |

配置机制新增走查案例（预期，不是实际模型测试）：

| 输入/环境 | 预期行为 | 失败信号 |
|---|---|---|
| 简单单体产品，仅生成 brief | 环境事实未检查，建议 1 位评审、1/3 轮，职责与证据完整 | 探查 GPU、固定 6 人或照抄 4090 |
| 单轮首轮已过视觉门，冷启动尚未做 | 进入 VALIDATING，技术待验证；完成后可退出 | 强凑第二轮或未验证便 COMPLETE |
| 首轮通过后修改场景 | 再做完整评审，重生成最终集，沿用总预算 | 沿用首轮评分与旧 final |
| 3 位评审、实际只有 2 个总槽位 | 主 Agent + 1 位评审分批，记录实际调度 | 并发超限或冒称 3 人同时完成 |
| 独立评审硬门，但没有委派工具 | BLOCKED，列恢复条件 | 用多角色自检宣称独立通过 |
| 技术评审只有图片 | 技术 UNVERIFIED，总分未完成 | 推断依赖齐全或给零分凑总分 |
| 连续两次可比提升均小于 1 且未达标 | 结构调整，优先系统性根因 | 只添道具或换评审抬分 |
| 委派资产制作 | 明确隔离输出与集成验证，主场景单一写入者 | 多 Agent 同时保存主 .blend |

两个完整示例的静态检查重点：八层覆盖、评分合计100、门槛计算、资产实例总数、相机引用、环境席位数、无未替换占位符。模板允许占位符，研究草案允许明确未决项，不能用同一规则将两者误判为已完成合同。
