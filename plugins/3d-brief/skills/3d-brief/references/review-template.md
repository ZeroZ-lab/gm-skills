# 固定评审提示词

制作开始时填入项目名、评审职责和对应评分维度，保存到项目 _work/reviews/REVIEW_PROTOCOL.md 并冻结。每轮只更新轮次和证据路径；目标或验收修改需用户授权，版本化协议并重新建立可比较基线。

## 提交给评审员的正文

你评审项目 {{PROJECT}}，本轮 {{ROUND}}，职责 {{ROLE}}，只评分这些维度：{{DIMENSIONS}}。
输入：完整 brief、评分锚点、资产/区域清单、相机职责表、本轮原始渲染与 contact sheet、上一轮同机位图；技术职责另附场景、脚本和冷启动日志。证据路径：{{EVIDENCE_PATHS}}。

按职责直接检查证据，不依据构建者的“已完成”总结。图片不可读时标记未验证，不猜分。原始文件保留；查看器需要缩放或裁切时标注派生图与原图的关系，近距判断需检查对应细节。技术通过不能仅由图片推断。

输出合并到 `_work/reviews/round_<n>/review.md`，多名评审员按职责分节，保留各自证据和分数：
1. 证据清单：实际打开的文件及覆盖范围，缺失/不可读内容。
2. 问题表：问题 ID、资产/区域 ID、相机/技术日志、严重度（关键/主要/次要）、根因、可执行修正。
3. 分数表：负责维度、满分、得分、锚点依据、扣分证据。未负责维度写 N/A，证据不足写 UNVERIFIED。
4. 回归表：相同机位 improved / unchanged / regressed，依据与尚未修复项。首轮写 baseline。
5. 可疑缺项与需要补拍的细节。

## 汇总规则

同一维度有多名负责评审员时取最低有效分；N/A 不参与，负责维度的 UNVERIFIED 阻止验收。全部维度均需覆盖。评审分数归档，不能换人重掷以获取高分；误读证据可追加更正说明，保留原记录。

可用且已授权委派时采用新鲜上下文评审员，按风险面合并职责而非硬凑人数。没有子代理时主代理按相同协议自检，标记“独立性未验证”；用户要求独立评审为硬门槛时不能用自检替代达标。
