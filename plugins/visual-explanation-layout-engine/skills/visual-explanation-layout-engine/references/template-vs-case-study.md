# Template Vs Case Study

Use this file before adding examples or expanding documentation.

## Template

The job of a template is to define a reusable method skeleton.

Template content should:

- demonstrate topology
- demonstrate tokens, routes, labels, and audit
- use abstract roles, phases, or placeholders
- remain reusable across domains without changing the layout method

## Case Study

The job of a case study is to show how the method lands in a specific domain.

Case-study content may:

- use domain terminology
- encode a real workflow or system
- show one concrete application of the method

## Hard Rules

1. Main templates do not use domain-specific nouns.
2. Main templates do not treat one business relationship as the default relationship.
3. Main template titles must be topology names or abstract task names, not business names.
4. Case studies must not replace template examples as the first method entrypoint.
5. If a reader cannot swap in a different domain without changing the layout logic, the example is a case study, not a template.
